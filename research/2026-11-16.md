### 2. Ask for the evidence behind each number, not for Claude's reasoning
[Anthropic Just Revealed How to Prompt Fable 5.2](https://www.youtube.com/watch?v=C45VVcCV9OY) (Ben AI, Nov 14, 14 min, transcript read; at 12:15)

**What it is:** Ben says Fable 5.2 may refuse to explain its internal thinking, and that Anthropic's testing found it sometimes states guesses as facts. So he asks for the source of each figure instead: "For every number in this summary, show me the exact source and the rows it came from."
**Why it matters:** You already require product facts to name a file or page (`claude/CLAUDE.md`, Product facts in replies), but that rule covers product claims, not numbers Claude computes or pulls from data. Extending it makes a guess visible in seconds (inferred fit).
**How to try it:** Next time Claude returns a summary built from data, add the sentence above. Check three numbers against the named rows.
**Suggested change:** `claude/CLAUDE.md`, Product facts in replies: add one sentence, "For any figure computed from data, name the source and rows, or say unverified." Your call on wording.
**Client angle:** For any client report built from a spreadsheet, asking for source rows per number lets a non-expert check it quickly.

## Worth knowing

### Hide the agent-written PR description behind a details tag
[Hide your slop PR descriptions behind <details><summary>](https://simonwillison.net/2026/Nov/9/details-summary/) (Simon Willison, Nov 9, post, read)
**What it is:** He writes a short human opening paragraph on each AI-written PR and puts the agent's full description inside a collapsed `<details><summary>` block, which GitHub renders.
**How to try it:** In a PR or issue comment, wrap the long text as `<details><summary>Claude</summary>` ... `</details>` and put two sentences above it.
**Why it is worth knowing:** A reader can decide in seconds whether a long AI write-up deserves their attention; it also works for any long AI-written summary shared with a client on GitHub.

### Tell Fable 5.2 the code is its own if you want it to tidy structure
[Prompting Claude Fable 5.2](https://simonwillison.net/2026/Nov/10/prompting-claude-fable-52/) (Anthropic docs, quoted by Simon Willison, Nov 10, quote read)
**What it is:** Anthropic says that when the prompt says the model owns the codebase, it consolidated duplicated code in about 75% of small-task runs, versus under 10% without the sentence.
**How to try it:** Add "You are the owner and long-term maintainer of this codebase, and its design is up to you." to a refactor prompt; leave it out when you want a minimal change.
**Why it is worth knowing:** One sentence changes how much the model restructures, so it is a switch for minimal fixes versus cleanup.

### Add a "finish your work" block for long unattended runs
[Anthropic Just Revealed How to Prompt Fable 5.2](https://www.youtube.com/watch?v=C45VVcCV9OY) (Ben AI, Nov 14, 14 min, transcript read; at 10:00)
**What it is:** Ben cites an Anthropic text block starting "Please avoid stopping while you still owe work the user asked for", which he says cut sessions ending with work left by about half, at about 30% more tokens (his figures from the guide, not checked).
**How to try it:** Paste that block, from Anthropic's Fable 5.2 prompting guide, into a project's instructions for a long job you walk away from, then compare how many runs end with a leftover list.
**Why it is worth knowing:** It targets the early-stop habit on unattended jobs, with a stated token cost.
