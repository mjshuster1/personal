## Kept items

### 1. Brief agents the way you would brief a person: job, why, guardrails, what done looks like
[15 Simple Tips to Use Claude 2.0 Better than 99% of People](https://www.youtube.com/watch?v=Q0ArTNWXeAU) (Ben AI, Nov 5, 25 min, transcript read; tip 2 at 2:04, the exit-criteria point at 3:37)

**What it is:** Ben, citing Claude Code's creator and Anthropic's own research, says newer models do better when you hand over a whole task with four things: the job, the why behind it, the roles and guardrails (what could go wrong, written as rules), and what done looks like (output format, quality bar, tone, length, or a past output you liked). He says the newer models tend to do too much rather than too little, so without exit criteria they keep going and burn tokens.
**Why it matters:** Your Token cost rule sends each subtask to an agent but says nothing about what the brief must contain (checked `claude/CLAUDE.md`; the only "done" wording is in the handoff-file line). A brief with a done condition also helps the cheap-model, low-effort agents you already prefer stop early. The claim that this changes output quality is Ben's, not tested here (inferred fit).
**How to try it:** When you delegate, write the brief with four short lines: Job, Why, Watch out for, Done when. For an unclear task, start with the line he credits to a Claude Code engineer: "interview me one question at a time about anything ambiguous."
**Suggested change:** `claude/CLAUDE.md`, "Token cost", after step 2: one line saying every agent brief states the goal, why it matters, what to avoid, and what done looks like. Your call on wording.
**Client angle:** For any task handed to an AI, write down what done looks like before sending it; it cuts both rework and cost.

## Worth knowing

### Tell Claude a memory folder exists; do not dictate what to write
[The components of agent memory](https://www.anthropic.com/research/components-of-agent-memory) (Anthropic, Nov 6, article, read in full)

**What it is:** Anthropic's account of how they give Claude memory between sessions. Telling Claude only that a memory folder is available was enough for the stronger models, and a rule such as "record only failures" made them worse. A "dreaming" pass, run between sessions, rechecks notes against the original transcripts and fixed a wrong note in their Pokémon test.
**How to try it:** In a project that keeps notes between sessions, say once that the folder exists and let Claude decide what is worth saving. Every so often, ask a fresh session to check the notes against the session logs and fix what no longer matches.
**Why it is worth knowing:** The results come from Anthropic's own benchmark and a game, so treat the size of the gains as theirs, not yours. It does match the "date the facts that go stale" idea already pending in your log.

### Audit scheduled routines: silent failures, dead outputs, model
[This ONE Skill Will 10x Your Claude Setup](https://www.youtube.com/watch?v=k6JWDYvHr3U) (Ben AI, Nov 6, 15 min, transcript read; routines at 13:15)

**What it is:** Ben's "detox" skill audits five parts of a Claude setup. The part not already in your log is scheduled tasks and cloud routines: list each with last run, whether it failed, and its model, then pause ones nobody reads and move simple ones from Opus to Sonnet. He says 6 of his 23 were in regular use and one was failing silently (his numbers, unverified).
**How to try it:** List your routines, then for each one check the last run, whether it failed, and whether anyone read the output in the past month. Pause the unread ones and try Sonnet on any that only summarize.
**Why it is worth knowing:** Routines run while you are away, so a broken one fails without anyone seeing it. The unused-skills and connectors points in the same video repeat the `/skill-doctor` entry already pending.

### Rewind instead of correcting Claude several times
[15 Simple Tips to Use Claude 2.0 Better than 99% of People](https://www.youtube.com/watch?v=Q0ArTNWXeAU) (Ben AI, Nov 5, 25 min, transcript read; tip 6 at 8:13)

**What it is:** When a chat drifts after two or three corrections, type `/rewind` (or press Escape twice), pick the earlier prompt, add the missing rule to it, and continue from there.
**How to try it:** Next time you correct Claude a second time on the same point, press Escape twice instead, pick the original prompt, add the rule to it, and resend.
**Why it is worth knowing:** Each correction stays in the chat and is re-read on every later message, so rewinding keeps the chat short and the wrong turn out of it.
