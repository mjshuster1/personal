### 1. Let /skill-doctor and /doctor find what loads for nothing
[Claude 2.0 is Insane (All Updates Explained)](https://www.youtube.com/watch?v=J5EbL1UaqG8) (Ben AI, Oct 25, 14 min, transcript read)

**What it is:** Ben covers new Claude Code commands. `/skill-doctor` shows what each installed skill costs in context and how often you use it, and flags unused ones. `/doctor` reads CLAUDE.md files, skills and settings for outdated or conflicting instructions that newer models no longer need.
**Why it matters:** Ben says `/skill-doctor` saved him about 20,000 tokens and `/doctor` flagged 312 problems across 404 files (his numbers, not checked against Anthropic docs). This gives a built-in way to do the unused-plugin cleanup that is still `pending` in the log, instead of guessing from `/context` (inferred fit).
**Suggested change:** Setup change, not a repo file: run `/skill-doctor` in a normal session and disable the plugin skills it flags, then run `/doctor` once against `claude/CLAUDE.md` and the files in `skills/` and `agents/`, and review its list before applying anything. Your call on each removal.
**Client angle:** Run the doctor commands on a client's setup before adding more skills; a lot of older instructions are dead weight on newer models.

### 2. Let a cheap model ask Opus for advice with /advisor
[Claude 2.0 is Insane (All Updates Explained)](https://www.youtube.com/watch?v=J5EbL1UaqG8) (Ben AI, Oct 25, 14 min, transcript read)

**What it is:** `/advisor` lets a run on Sonnet or Haiku consult a stronger model such as Opus at key moments, so the stronger judgment is paid for only where it matters. Ben uses it for inbox cleanup, with Opus drafting only the important replies.
**Why it matters:** Your Token cost rule picks one model per subtask. Advisor is a middle route for subtasks that are mostly mechanical but have one hard decision (inferred fit). I could not verify from the video whether advisor applies inside agents spawned by the Agent tool.
**Suggested change:** `claude/CLAUDE.md`, "Token cost" step 2: add one line that for a mostly mechanical subtask with one judgment call, a cheap model with `/advisor` on is an option. Test it on one routine before writing the line.
**Client angle:** For repetitive client work such as inbox triage, run the cheaper model and escalate only the judgment calls.

## Worth knowing

### Side chats: ask about a long task without polluting it
[Claude 2.0 is Insane (All Updates Explained)](https://www.youtube.com/watch?v=J5EbL1UaqG8) (Ben AI, Oct 25, 14 min, transcript read)

**What it is:** In the Claude Code desktop app, a side chat can read the whole main chat so far, answer questions or review the work, and stays out of the main context; it persists and can send messages back.
**Why it is worth knowing:** It keeps questions and reviews from adding tokens to a long chat. Note it reviews with the same model and context, so it does not replace a separate-agent review.

### Nested sessions: one coordinator chat that starts task chats
[Claude 2.0 is Insane (All Updates Explained)](https://www.youtube.com/watch?v=J5EbL1UaqG8) (Ben AI, Oct 25, 14 min, transcript read)

**What it is:** A main chat starts other chats inside it (projects on Pro and Max, nested sessions on Team), sends them messages, checks their work and reports back, so each task keeps its own context.
**Why it is worth knowing:** Same "one chat per task" habit you already follow, with a coordinator that knows where each one stands. Rollout is partial and Ben's description of plan differences is unverified.
