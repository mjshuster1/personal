# Document review

Four passes, always in this order. Each pass finishes before the next starts.
Don't polish a sentence in pass 4 that pass 1 or 3 should have cut.

## Pass 1: Substance

Is it right, and is it the right document?

- Every factual claim: true, and traceable to a source (doc, call, data). Flag
  anything that can't be traced as UNVERIFIED rather than assuming it's fine.
- Claims about what a product or team can do match what it actually does today.
- The main point is the one the reader needs, stated where they'll see it.
- Nothing important is missing for this reader and this decision.
- The argument holds: conclusions follow from what comes before.

**Gate:** if pass 1 finds a problem that changes the argument, structure, or
main point, report it and stop. Ask whether to continue. The later passes
would be reviewing text that is about to change.

## Pass 2: Slop

Language that sounds generated or generic instead of written by someone who
knows the subject.

- If the `de-slop` skill is available, use its tell list, the `personal-voice` skill, and any company voice files as
  the standard for this pass (diagnose only, don't hand back rewritten text
  unless asked).
- Otherwise flag: em dashes; filler openers and closers; stacked hedges;
  "not X but Y" and rule-of-three constructions used for rhythm; vague
  intensifiers; marketing words that make no concrete claim; jargon the
  intended reader wouldn't use.

## Pass 3: Bloat

Content that costs the reader time without adding anything.

- Sections, paragraphs, or sentences that repeat a point already made.
- Background the reader already knows.
- Detail that doesn't serve the reader's decision.
- Anything that can go with no loss. Say what to cut, not just that it's long.

## Pass 4: Clarity

What remains, made easy to read.

- Sentences a reader would have to read twice.
- Ambiguous references ("this", "it", "they") and undefined terms.
- Order: answer first, then support.
- Headings, bullets, and paragraph breaks that match the content's shape.

## Output

Findings grouped under the four pass headings, in order. For each finding:
location (quote or section), the problem, the proposed fix. Mark each
finding as an instance or a pattern; for a pattern, list the other places it
occurs. If a pass finds nothing, say so in one line.

Don't edit the document itself unless asked. If asked to apply fixes, apply
them in pass order.
