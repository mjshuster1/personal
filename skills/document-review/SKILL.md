# Document review

Four passes, always in this order. Each pass finishes before the next starts.
Don't polish a sentence in pass 4 that pass 1 or 3 should have cut.

## Pass 1: Substance

Is it the right document for this reader?

- Every line serves the actual reader. Cut lines that answer someone else's
  question: an internal concern, or a point raised by a different person on a call.
- The main point is the one the reader needs, stated where they'll see it.
- Nothing important is missing for this reader and this decision.
- The argument holds: conclusions follow from what comes before.
- Don't flag product, roadmap, or capability claims as unverified or
  overstated. Matt owns those; what's true about the product changes faster
  than any document.

**Gate:** if pass 1 finds a problem that changes the argument, structure, or
main point, report it and stop. Ask whether to continue. The later passes
would be reviewing text that is about to change.

## Pass 2: Slop

Language that sounds generated or generic instead of written by someone who
knows the subject.

- If the `de-slop` skill is available, use its tell list, the `personal-voice` skill, and any company voice files as
  the standard for this pass (diagnose only, don't hand back rewritten text
  unless asked).
- Otherwise flag: em dashes; filler openers and closers; stacked hedges;
  "not X but Y" and rule-of-three constructions used for rhythm; vague
  intensifiers; marketing words that make no concrete claim; jargon the
  intended reader wouldn't use.

## Pass 3: Bloat

Content that costs the reader time without adding anything.

- Sections, paragraphs, or sentences that repeat a point already made.
- Background the reader already knows.
- Detail that doesn't serve the reader's decision.
- Anything that can go with no loss. Say what to cut, not just that it's long.

## Pass 4: Clarity

What remains, made easy to read.

- Sentences a reader would have to read twice.
- Ambiguous references ("this", "it", "they") and undefined terms.
- Order: answer first, then support.
- Headings, bullets, and paragraph breaks that match the content's shape.
- Edits made to fit a page: re-read them for what they now say.
- Anything that renders (page, Artifact, PDF): check the rendered output at
  full width and phone width for one-word last lines, headings included.

## Deep review (optional)

For documents that drive a decision or go outside the company, or when Matt
asks for a deep review. Run it after the four passes, in this order, top layer
first. If a higher layer finds a structural problem, still do the lower
layers, but mark a sentence "moot if X" when a structural fix would delete it.

1. **Goals.** State the document's goals in one line each, in the author's
   words.
2. **Section jobs.** Give each section a one-line job and the goal it serves.
   Flag sections with no job, two jobs, or the wrong position.
3. **Reverse outline.** Write one line per paragraph, table or bullet group,
   then read only those lines. Flag points that are off-job, out of order,
   repeated, or that leave a gap in the argument. Name any trade-off the
   document implies but never states.
4. **Sentences.** Test each sentence: serves its paragraph's point; new, not
   said elsewhere; connects to the sentence before (known information first,
   new last); supported by a source; missed if cut. Report failures only, with
   a replacement.

Report layers 1 to 3 as short lists and layer 4 as a table (location, test
failed, problem, replacement, fix or consider), then the top three changes by
impact. It costs two to three times a four-pass review, so don't run it on
every draft.

## Output

Findings grouped under the four pass headings, in order. For each finding:
location (quote or section), the problem, the proposed fix. Mark each
finding as an instance or a pattern; for a pattern, list the other places it
occurs. If a pass finds nothing, say so in one line.

Don't edit the document itself unless asked. If asked to apply fixes, apply
them in pass order.
